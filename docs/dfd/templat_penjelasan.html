DFD Dashboard Lokasi Pos Gawat Darurat Kota Bekasi

Data Flow Diagram (DFD) menggambarkan dari mana data datang, diproses oleh apa, disimpan di mana, dan keluar ke siapa. Halaman ini menjelaskan DFD dari nol, lalu menunjukkan tiga diagram yang sudah disusun dari prototipe dashboard Anda, berikut daftar pekerjaan sebelum DFD siap masuk skripsi.

1 · Apa itu DFD

Peta perjalanan data, bukan urutan langkah

DFD hanya menjawab pertanyaan data apa mengalir ke mana. DFD tidak menunjukkan urutan waktu, percabangan if/else, atau perulangan; itu tugas flowchart atau activity diagram. Karena itu tidak ada simbol "mulai", "selesai", atau belah ketupat keputusan di DFD.

DFD digambar bertingkat. Tingkat paling atas melihat sistem sebagai satu kotak hitam; setiap tingkat di bawahnya "membuka" satu proses menjadi beberapa proses yang lebih rinci, sampai setiap proses cukup sederhana untuk dijelaskan dengan beberapa kalimat atau pseudocode.

2 · Empat simbol

Hanya ada empat jenis bentuk

Ada dua gaya gambar yang umum dipakai: Yourdon/DeMarco (proses berupa lingkaran) dan Gane–Sarson (proses berupa persegi bersudut tumpul). Isinya sama; pakai salah satu secara konsisten, sesuai yang diminta pembimbing atau panduan jurusan. Diagram di halaman ini tersedia dalam kedua gaya.

Entitas eksternal

Orang atau sistem di luar dashboard yang memberi atau menerima data. Di sini: Admin, Perencana, dan Layanan Rute (OSRM).

Proses

Sesuatu yang mengubah data masuk menjadi data keluar. Diberi nomor dan nama berupa kata kerja + objek, misalnya "Tampilkan Solusi". Kiri: Yourdon, kanan: Gane–Sarson.

Penyimpan data

Tempat data diam: tabel database atau file. Diberi kode D1, D2, … dan nama berupa kata benda. Penyimpan data inilah yang nanti menjadi tabel di ERD.

Aliran data

Panah berlabel yang menunjukkan data berpindah. Labelnya kata benda (datanya), bukan kata kerja: "solusi Pareto", bukan "kirim solusi".

3 · Diagram konteks (level 0)

Sistem dilihat dari luar

Seluruh dashboard digambar sebagai satu proses bernomor 0. Yang terlihat hanya siapa saja yang berinteraksi dengannya dan data apa yang keluar-masuk. Penyimpan data belum digambar di level ini.

4 · DFD level 1

Proses 0 dibuka menjadi lima proses

Proses 1.0 dan 2.0 adalah bagian Admin (direncanakan untuk prototipe berikutnya). Proses 3.0–5.0 adalah yang sudah ada di prototipe sekarang. Penyimpan data D1–D6 mulai muncul di level ini. Perhatikan bahwa semua aliran yang menyentuh entitas eksternal sama persis dengan diagram konteks; inilah yang disebut balancing.

5 · DFD level 2 proses 2.0

Membuka proses yang paling rumit

Tidak semua proses perlu level 2. Yang dibuka hanya proses yang masih terlalu besar untuk dijelaskan dalam beberapa kalimat. Proses 2.0 dibuka karena di dalamnya ada empat pekerjaan berbeda. Nomor anak proses mewarisi nomor induknya: 2.1, 2.2, 2.3, 2.4. Proses 1.0 digambar putus-putus karena ia bukan bagian 2.0, hanya sumber aliran "hak akses admin".

9 · File di proyek

Mengedit dan memakai diagramnya

  • Semua file ada di docs/dfd/. File .svg bisa langsung disisipkan ke Word (Insert → Pictures) atau LaTeX.
  • File .drawio dibuka di app.diagrams.net (gratis). Di sana Anda bisa memindahkan bentuk, mengganti nama, lalu File → Export as → PNG/PDF.
  • Nama file berakhiran -gane-sarson adalah versi notasi Gane–Sarson.
  • Kalau isi DFD berubah besar, ubah daftar bentuk dan aliran di docs/dfd/buat_dfd.py lalu jalankan ulang; semua file terbentuk lagi dengan nama aliran yang konsisten.
